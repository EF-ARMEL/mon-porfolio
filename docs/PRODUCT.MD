# Portfolio — Product Specification

## 1. Présentation

Ce projet est le portfolio personnel de Franck Armel, développeur web junior spécialisé dans le développement d'applications web et intéressé par le développement assisté par l'intelligence artificielle.

Le portfolio doit présenter à la fois :

* la personne ;
* le parcours ;
* les compétences ;
* les projets réalisés ;
* la manière de travailler ;
* l'utilisation de l'IA dans le développement ;
* les connaissances techniques ;
* les objectifs futurs ;
* la capacité à concevoir des expériences web modernes.

Le portfolio doit être considéré comme une véritable application web et non comme une simple page CV.

---

## 2. Objectif principal

L'objectif principal est de permettre à un visiteur de comprendre rapidement :

1. qui est Franck Armel ;
2. ce qu'il sait faire ;
3. ce qu'il a déjà réalisé ;
4. comment il travaille ;
5. comment il utilise l'intelligence artificielle dans son développement ;
6. ce qu'il souhaite construire à l'avenir ;
7. comment le contacter ou collaborer avec lui.

Le portfolio doit également servir de démonstration technique.

Le site doit montrer les compétences plutôt que simplement les énumérer.

---

## 3. Positionnement

Le portfolio doit présenter Franck Armel comme un développeur :

* en début de carrière ;
* sérieux dans son apprentissage ;
* orienté développement web ;
* intéressé par le frontend et le backend ;
* capable d'utiliser des outils modernes ;
* capable d'utiliser l'IA comme outil de développement ;
* intéressé par l'architecture, le design et l'expérience utilisateur.

Le positionnement doit rester honnête.

Ne pas présenter comme maîtrisée une technologie uniquement étudiée ou en cours d'apprentissage.

---

## 4. Public cible

Le portfolio doit pouvoir être compris par plusieurs types de visiteurs.

### Recruteurs

Ils doivent pouvoir comprendre rapidement :

* le profil ;
* les compétences ;
* les projets ;
* le parcours ;
* les moyens de contact.

### Développeurs

Ils doivent pouvoir découvrir :

* les choix techniques ;
* les projets ;
* les méthodes de développement ;
* les connaissances techniques ;
* le travail avec l'IA ;
* certaines interactions techniques du portfolio.

### Clients ou entreprises

Ils doivent pouvoir comprendre :

* les types de projets pouvant être réalisés ;
* les compétences disponibles ;
* la manière de collaborer ;
* comment prendre contact.

### Visiteurs non techniques

Ils doivent pouvoir comprendre le parcours et les projets sans avoir besoin de connaissances en programmation.

---

## 5. Expérience générale

Le portfolio doit être une expérience immersive et narrative.

Le visiteur ne doit pas simplement parcourir une succession de blocs contenant :

* titre ;
* texte ;
* image ;
* bouton.

La navigation doit utiliser intelligemment :

* scroll ;
* mouvement ;
* transitions ;
* typographie ;
* profondeur ;
* interactions ;
* animation ;
* éventuellement 3D.

Ces éléments doivent renforcer le contenu et non le remplacer.

---

## 6. Sections principales

La structure finale pourra évoluer pendant le développement, mais le portfolio doit explorer au minimum les domaines suivants.

### 6.1 Hero

Présenter immédiatement :

* identité ;
* rôle ;
* proposition de valeur ;
* élément visuel fort ;
* appel à l'exploration du portfolio.

Le Hero doit donner immédiatement l'identité visuelle du site.

---

### 6.2 À propos

Présenter :

* qui je suis ;
* mon parcours ;
* ma manière d'apprendre ;
* ma manière de travailler ;
* ce qui m'intéresse dans le développement.

La section doit rester personnelle et éviter le texte générique de type CV.

---

### 6.3 Parcours

Présenter progressivement :

* apprentissage ;
* formations ;
* expériences ;
* projets ;
* évolution des compétences.

Le parcours peut être présenté sous forme de narration interactive ou de timeline.

---

### 6.4 Projets

Les projets constituent une partie centrale du portfolio.

Chaque projet doit pouvoir présenter selon sa nature :

* nom ;
* contexte ;
* problème ;
* solution ;
* fonctionnalités ;
* technologies ;
* rôle personnel ;
* difficultés rencontrées ;
* résultats ;
* liens ;
* captures ou démonstrations.

Les projets doivent démontrer les compétences plutôt que simplement afficher une liste de technologies.

---

### 6.5 IA × Développement

Cette section doit montrer comment Franck Armel utilise l'intelligence artificielle dans son processus de développement.

L'objectif n'est pas de donner l'impression que l'IA écrit simplement le code à sa place.

Le portfolio doit montrer une démarche structurée comprenant notamment :

* réflexion ;
* recherche ;
* documentation ;
* Claude Code ;
* MCP ;
* skills ;
* Second Brain ;
* génération ou modification de code ;
* vérification ;
* tests ;
* validation humaine ;
* amélioration.

Le message central doit être :

> L'IA est un outil intégré dans un processus de développement structuré.

---

### 6.6 Défi développeur

Le portfolio peut proposer une expérience interactive destinée aux visiteurs techniques.

Le visiteur peut être invité à répondre à des questions ou résoudre de petits problèmes liés au développement.

Cette expérience peut permettre de montrer :

* logique ;
* raisonnement ;
* JavaScript ;
* React ;
* architecture ;
* bonnes pratiques ;
* compréhension du code.

Un visiteur non développeur doit pouvoir choisir de passer cette expérience et continuer normalement la navigation.

Cette section doit rester optionnelle et ne doit jamais empêcher l'accès au reste du portfolio.

---

### 6.7 Compétences

Présenter les compétences techniques de manière visuelle et contextualisée.

Les technologies peuvent être regroupées par catégories :

* Frontend ;
* Backend ;
* Base de données ;
* Outils ;
* IA / développement assisté ;
* Architecture ;
* Design / UI.

Les niveaux affichés doivent rester honnêtes et correspondre au niveau réel.

---

### 6.8 Connaissances

Cette section peut présenter certaines connaissances acquises au fil des apprentissages.

Elle peut notamment aborder :

* développement logiciel ;
* architecture ;
* bonnes pratiques ;
* performance ;
* sécurité ;
* React ;
* conception UI ;
* animation ;
* IA appliquée au développement.

L'objectif est de montrer la progression et la compréhension, pas simplement de reproduire une liste de cours suivis.

---

### 6.9 Rêves et futur

Présenter ce que Franck Armel souhaite construire et apprendre dans les prochaines années.

Cette section peut présenter :

* technologies à approfondir ;
* types de produits à créer ;
* domaines qui l'intéressent ;
* objectifs professionnels ;
* projets futurs ;
* vision autour de l'IA et du développement.

Cette section doit montrer une direction personnelle plutôt qu'une promesse irréaliste.

---

### 6.10 Collaboration

Présenter clairement les possibilités de collaboration.

Le visiteur doit pouvoir comprendre :

* pourquoi contacter Franck ;
* pour quels types de projets ;
* comment démarrer une discussion.

---

### 6.11 Contact

Le portfolio doit permettre au visiteur d'envoyer un message.

Le formulaire pourra contenir notamment :

* nom ;
* email ;
* sujet ;
* message.

Le système doit permettre au propriétaire du portfolio de consulter les messages depuis l'administration.

---

## 7. Mode clair et mode sombre

Le portfolio doit proposer deux thèmes visuels :

* mode sombre ;
* mode clair.

Le changement de thème doit préserver :

* lisibilité ;
* contraste ;
* identité visuelle ;
* cohérence des composants ;
* animations ;
* illustrations ;
* éléments 3D.

Le thème ne doit pas simplement inverser mécaniquement toutes les couleurs.

---

## 8. Administration

Le portfolio doit posséder une interface d'administration privée.

L'administration doit permettre de modifier le contenu du portfolio sans devoir modifier directement le code source.

Le système doit notamment permettre de gérer :

* Hero ;
* présentation ;
* parcours ;
* projets ;
* compétences ;
* connaissances ;
* section IA ;
* questions du défi développeur ;
* rêves ;
* contenu de contact ;
* messages reçus ;
* paramètres du portfolio.

Le contenu public doit être découplé autant que possible de son administration.

---

## 9. Gestion des projets

L'administrateur doit pouvoir :

* créer un projet ;
* modifier un projet ;
* supprimer un projet ;
* publier ou dépublier un projet ;
* modifier son contenu ;
* ajouter des technologies ;
* ajouter des images ;
* ajouter des liens ;
* définir son ordre d'affichage.

---

## 10. Gestion des messages

Les messages reçus depuis le formulaire de contact doivent être accessibles depuis l'administration.

Chaque message doit pouvoir posséder un état permettant notamment de distinguer :

* nouveau ;
* lu ;
* répondu ;
* archivé.

Les détails exacts seront définis dans `docs/admin.md` et `docs/database.md`.

---

## 11. Contenu dynamique

Le contenu qui doit pouvoir évoluer régulièrement doit être stocké dans le système de données plutôt que codé en dur dans les composants lorsque cela est pertinent.

Cependant, tout ne doit pas devenir dynamique.

Les éléments purement structurels ou techniques peuvent rester dans le code.

L'objectif est de trouver un équilibre entre :

* flexibilité ;
* simplicité ;
* performance ;
* maintenabilité.

---

## 12. Performance

L'expérience visuelle ne doit pas transformer le portfolio en site lent.

Le produit doit accorder une attention particulière à :

* chargement initial ;
* images ;
* vidéos éventuelles ;
* 3D ;
* animations ;
* JavaScript côté client ;
* appareils mobiles ;
* connexions lentes.

Les effets visuels doivent être conçus avec une stratégie de dégradation lorsque nécessaire.

---

## 13. Responsive

Le portfolio doit fonctionner sur :

* grands écrans ;
* ordinateurs portables ;
* tablettes ;
* smartphones.

Les expériences de scroll et de 3D doivent être adaptées aux capacités des appareils.

Une interaction conçue pour desktop ne doit pas être forcée telle quelle sur mobile.

---

## 14. Accessibilité

L'expérience visuelle doit rester accessible.

Prévoir notamment :

* navigation clavier ;
* structure HTML sémantique ;
* contrastes suffisants ;
* textes alternatifs ;
* états de focus ;
* prise en compte de `prefers-reduced-motion`.

Les animations ne doivent pas être indispensables à la compréhension du contenu.

---

## 15. Évolution du produit

Cette spécification constitue la vision actuelle du portfolio.

Elle pourra évoluer pendant le développement.

Toute évolution importante du produit doit être documentée avant ou après son implémentation selon son importance.

Les décisions importantes doivent être ajoutées à :

`docs/decisions.md`

---

## 16. Principe directeur

Le portfolio doit raconter une histoire autour de la personne, de ses compétences et de son évolution.

Il doit démontrer simultanément :

**Qui je suis → ce que j'ai appris → ce que je sais construire → comment je travaille → comment j'utilise l'IA → ce que je veux construire ensuite.**

L'expérience visuelle, le contenu et la technologie doivent servir cette narration.
